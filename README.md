# interval-timer Ver. 0.2

16:9の横型ディスプレイに投影する、サーバー不要のインターバルタイマーです。

**公開アプリ:** https://kojikomatsuzaki.github.io/interval-timer/

**[操作チュートリアル](https://kojikomatsuzaki.github.io/interval-timer/tutorial.html)** — 基本操作から音源の選択、投影まで、実際の操作順に説明しています。

## 使い方

1. 「⚙ 設定」を開き、ACT・RESTの秒数、繰り返し回数、進行方式を入力し「保存してタイマーへ」を押します。
2. STARTで電子音付きの3秒予告を開始。ACTは経過時間をカウントアップします。
3. STOPは現在の時間を保持して一時停止。STARTで続きから再開します。
4. RESETで最初に戻ります。実行中・一時停止中の時間設定はロックされます。音声ON/OFFはいつでも変更できます。
5. 初期表示はタイマーのみで、16:9の表示が画面内に収まります。「⚙ 設定」から設定を重ねて開き、「保存してタイマーへ」で閉じます。閉じるボタン・Escキーでもタイマーへ戻れます。「全画面」で投影画面を表示できます。全画面中も設定を開けます。

ACT・RESTの初期値は10分・1分、繰り返しは3回です。時間入力の単位は**秒**です。

## 自動と手動

- **自動:** 最初の予告 → ACT → REST → 次のACT。RESTの最後の3秒に予告音、REST終了時にホーンが鳴り、そのまま次のACTを開始します。RESTとは別の3秒は加算しません。
- **手動:** ACT終了で待機し、STARTでRESTへ。REST終了でも待機し、STARTで3秒予告を経て次のACTへ進みます。
- RESTが0秒の場合は休憩を省略し、次のACTの前に開始予告を入れます。
- 最終ACT終了でFINISHを表示します。最終ラウンドの後にRESTはありません。
- 開始予告中のSTOPも一時停止です。再開時に予告を最初からやり直しません。

## 音声

| タイミング | 初期音源・再生回数 |
| --- | --- |
| 開始予告 3・2・1 | 電子音各1回 |
| ACT開始 | 既存のレゲエホーンMP3 1回（再配布許諾は未確認） |
| ACT中の毎分 | 小音量のベル1回 |
| ACT終了1分前 | 小音量のベル2回、間隔0.18秒 |
| ACT終了（最終回を含む） | プロレスのゴング風の合成音5回、間隔0.2秒 |

10分のACTでは1〜8分にベル1回、9分に2回、10分にゴング5回。終了前ベルと定期ベルが同時なら終了前ベルを優先します。ACTが1分以下では「終了1分前」を鳴らしません。定期ベル間隔・終了前ベル時刻も変更可能です。

開始音は最新Ver. 0.1の指定を引き継ぎます。既存第三者MP3の同梱許諾は未確認で、詳しくは下のクレジット節を参照してください。新たに追加した標準WAVは数式から生成した音で、第三者の録音を利用していません。画面の詳細設定で標準音・合成音・無音を選択し、全体音量・通知別の音量・再生回数・間隔を調整できます。

従来のMP3/WAV URL・相対パス指定も「URL・相対パスを指定…」で維持します。外部音源にはCORSの許可が必要で、音源の取得通信が発生します。標準・URL音源の読み込み失敗時は警告を表示し合成音へ戻します。通知ごとの「無音」は他の通知に影響せず、音声OFFは試聴を含めてすべてを停止します。

ブラウザの制約により、音声はSTART・試聴・音声ONなどのユーザー操作で有効になります。音声OFF中は試聴もミュートされます。

## YAMLを正本にする設定管理

- リポジトリの [`config/timer.yaml`](config/timer.yaml) が初期設定です。
- 画面入力とYAML編集は同じ設定構造を使用します。画面変更はYAML欄に同期し、「保存してタイマーへ」で適用します。
- YAML欄の直接編集は「YAMLを反映」で適用します。
- 適用済み設定はlocalStorageへ保存し、同じブラウザで次回復元します。保存不可の場合は警告します。
- YAMLファイルの読み込み、ダウンロード、初期設定への復元に対応します。
- GitHub Pagesからリポジトリのファイルは直接更新できません。全端末共通の初期設定を変える際は、ダウンロードしたYAMLを `config/timer.yaml` にコミットしてください。
- ブラウザ保存済み設定がある端末はそれを優先します。リポジトリの新しい初期値に戻すには「初期設定に戻す」を押してください。
- 時間・表示・標準音源の設定はYAMLで管理できます。ローカル音源・全画面・パネル開閉・START/STOP/RESETは一時的な状態として扱います。

`timer` の時間は秒、`audio` の音量は0〜1です。`countdown_seconds` は0〜30の整数、`rounds` は1〜999の整数。ACTは1〜86400秒、RESTは0〜86400秒。予告がRESTより長い場合、REST内で可能な整数秒分の予告だけ鳴ります。予告0秒では開始ホーンのみです。未対応のキー・範囲外の値・壊れたYAMLは拒否し、現在の設定を保持します。

## 時間精度

`performance.now()` を基準に、約50msごとに経過時間を再計算します。更新回数の加算を使わず、ACT・REST境界の遅れを次区間に引き継ぐため、遅延が累積しません。STOP時は経過を保持し、START時に時計の基準を更新します。

前景での計測・音声通知の目標許容誤差は±0.5秒。音声は画面から独立したWeb Audio時計に最大150ms先読みで予約し、連打も予約再生します。開始ホーンは区間切り替え時の更新で再生します。OS・ブラウザの負荷や音声出力機器の遅延により厳密な保証はできません。

非表示時や端末のスリープ中は、表示・通知のリアルタイム性を保証できません。復帰時は区間を進め、500ms以上過去の音を一斉再生しません。ブラウザ・OSによってスリープ中の単調増加時計の挙動は異なるため、投影中は画面を前景に保ってください。対応ブラウザではScreen Wake Lockを取得します。表示はACTの整数秒を切り捨て、RESTの残り整数秒を切り上げます。詳細設定で0.1秒表示にできます。

## ローカル音源とプライバシー

「自分の音源を使用…」で端末のファイルを選択します。MP3・WAVを基本とし、その他の音声形式はブラウザがデコードできる場合に使用できます。初期上限は20 MiB（20 × 1024 × 1024バイト）。`audio.local_max_bytes` で変更できます（1〜100 MiB）。

**利用者が選択した音源ファイルはブラウザ内だけで使用します。運営者のサーバー、GitHub、外部APIへ送信せず、localStorage・IndexedDB・YAML・その他の永続ストレージにも保存しません。**

File API・Blob URLを使用し、ブラウザ内のBlob URLから読み込んだ音声をWeb Audioで再生します。別のローカル音源・標準音源への切り替え、ページ終了時にBlob URLを解放します。読み込み中の選択変更も古い結果を採用しません。不正ファイル・上限超過・キャンセル時は前の有効な選択を保持します。

選択中はファイル名と一時利用の案内を画面に表示します。プルダウンに表示する標準音源は、再読み込み後に戻る音源です。「標準音源に戻す」または別の標準音源を選ぶと解除できます。再読み込み・ページ終了でも解除されます。保存・YAML書き出しには標準選択のみを含め、ローカルのファイル内容・ファイル名・Blob URLを含めません。

アプリ自体と標準音源の取得にはGitHub Pagesへの通信が発生します。従来の外部URL音源を指定した場合も配信元への取得通信は発生しますが、選択したローカルファイルを送信する処理はありません。

## YAML音源メタデータと互換性

```yaml
version: "0.2"
# timer / display はVer. 0.1と同じ
# 以下はaudio部分の抜粋です。完全な設定はconfig/timer.yamlを参照。
audio:
  local_max_bytes: 20971520
  start:
    selected: short_horn
    volume: 0.8
    count: 1
    interval_seconds: 0.15
  catalog:
    short_horn:
      name: 短いホーン
      description:
        text: 数式から生成した、短い開始通知音です。
        language: ja
        author: "OpenAI Codex（AI草稿）"
        created: "2026-10-09"
      source: audio/short-horn.wav
      provider: "Interval Timer（プログラム生成）"
```

- IDは英小文字始まり、英小文字・数字・ハイフン・アンダースコアの64文字以内です。名前は利用者向けの表示、selectedは内部参照です。
- descriptionはオブジェクトで、text・language（BCP 47）・author（説明文の作成主体、未確認ならnull）・created（説明文の作成日、ISO 8601のYYYY-MM-DD文字列）を管理します。任意のmodifiedも同じ日付形式で追加できます。
- 新規説明はAI草稿として明記しています。Hiroshi Komatsuzaki本人の執筆として記録していません。description.authorは音源の著作権者、createdは音源の制作日ではありません。
- provider・attribution_url・license・rights_holderは任意項目です。権利者・許諾不明の場合に推測で補完しません。
- 旧sourceはカタログの同一sourceに対応づけ、未登録のURL・相対パスも安定IDで移行します。音量・回数・間隔・時間・表示・進行方式を維持します。sourceとselectedの同時指定は拒否します。
- 保存先は `interval-timer:0.2`。0.2保存がなければ旧 `interval-timer:0.1` を読み取り、移行して保存します。旧キーは戻せるよう保持します。保存済みカタログに公開YAMLの追加音源をマージし、未知のIDは通知に対応する合成音に戻して警告します。
- 未対応キー・壊れたYAMLは拒否し、編集前の有効な設定を維持します。起動時の破損設定は初期値へ、初期YAML取得失敗は合成音の緊急設定へ戻します。Blob/data/file URLは永続設定に指定できません。
