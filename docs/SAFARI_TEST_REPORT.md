# macOS Safari追加テスト記録

実施日：2026-10-10。利用者が「リモートオートメーションを許可」を有効にした後に実施。

## 環境・方法

インストール済みmacOS Safariのプライベートウィンドウを、コンピュータユースで実画面操作しました。通常ウィンドウの保存設定を変更せず、端末設定の追加変更も行っていません。SafariDriver 27.2は新規セッション接続がタイムアウトしたため、WebDriverによる自動テストではありません。

最初に公開版main `a377a6861479ce6389167ab60550b24c47275120` を確認し、修正後はローカルHTTPサーバーで以下を再検証しました。

## 確認結果

- 横16:9のタイマー、Ver. 0.2表示、設定の初期非表示。
- YAMLカタログの名称・説明表示、標準音源選択・試聴操作。
- 自動進行：ACT20秒・REST10秒・2ラウンドでRESTへの移行、次ACT、最終FINISH、RESET。
- STOPでACT表示停止、STARTで続きから再開。
- 手動進行：ACT6秒・REST3秒・2ラウンド・開始予告1秒で、ACT/REST終了時の待機、STARTで次区間、FINISH、RESET。
- 実際のファイル選択ダイアログでローカルMP3とWAVを選択・切り替え・試聴操作。WAVを手動タイマー開始音として指定。
- 20 MiB超のファイル、不正なWAVでエラーを表示し、直前の正常なWAV選択を維持。
- YAML表示にローカルファイル名・Blob URL・音声データを含めず、永続的な標準音源IDを保持。
- 標準音源への復帰、再読み込みによるローカル解除、保存済み時間・手動進行設定の復元。
- 通知ごとの無音、全体音声OFF、全画面表示、全画面中の設定開閉。
- チュートリアルへの移動、タイマーへ戻るリンク。

## 発見・修正した問題

1. Safariではselectの変更からファイル選択が開かない場合がありました。直接ユーザーが押せる「自分の音源を選ぶ」ボタンを追加しました。メニュー方式も維持しています。
2. ファイル選択後の非同期処理でAudioContext.resumeを待つとSafariで読み込みが完了しない場合がありました。デコードと再生許可の取得を分離し、試聴・START時に再生を有効化します。
3. 試聴の読み込み直後に設定適用すると、閉じたプレイヤーから不要な警告が出ました。取消済みの非同期結果を無視し、古いコンテキスト参照を使わないよう修正しました。

修正の回帰検証として単体テスト2件を追加し計21件成功。Chrome/Edgeは各19項目とキャッシュ対策各1件、計40項目成功。

## 検証範囲の限界

スピーカーからの聞き取り・音響遅延測定は実施していません。Safari上では音源デコード、再生操作、エラー有無、タイマー状態を確認しました。Safari固有の通信キャプチャ、Blob解放の計測、旧0.1保存データ投入、YAML読込失敗・不存在音源の故障注入は繰り返していません。これらは単体テストまたはChrome/Edgeの検証記録を参照してください。ローカル音源の外部送信・永続保存処理は追加していません。

iPhone Safariは実機がなく未実施。SafariDriverによる自動接続も未成立です。macOS Safariでの実画面確認と区別します。
